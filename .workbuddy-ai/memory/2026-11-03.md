## 11-04 08:50 文本排查的关键事实
- 参考版本 = 19:12 构建 (9015415 字节, build 19:11:57)。回退后重新构建恰好也是 9015415 字节。
- `text_draw_engine_ex` 里无 '\n' 分支 `break` 在绘制之前 → 单行字符串一个字都不画(存档/职业介绍/对话/角色信息全灭)。已修。
- 图集"马赛克"：引擎为同一行建 512 宽字符串图像并放大铺满整个框叠在我们文字上。
  现在填充改成"延迟一帧"决策 (strimg_pending_add / strimg_pending_tick)：
  引擎请求先挂起，下一帧主循环顶部再看我们自己是否也画了这一行，是则留空。日志 `text: atlas N left empty, we draw '...'`。
  **不要在绘制回调里发 GL 调用** —— 上一版在 our_text_note 里直接 glTexSubImage2D 清空图集，导致存档后卡死(watchdog 栈顶 UIPorting_DrawNumber → GRPX_DrawStringWithFont)。
- 关键实测：`draw_text = 0` 关掉移植层绘制后，**游戏内文本全部消失**（只有标题画面的字还在，标题走引擎 font.fnt 原生路径）。
  → 对话/存档/角色信息这些行引擎自己不画，必须靠我们的 FreeType；所以 draw_text 不能设 0。
- 新增日志 `text: draw NONWHITE ...` 抓到：NPC 名牌 `黑暗教团士兵` 在 (508,43) 被我们用 **col 000000 纯黑** 画出来 → 黑条上黑字 = "只有黑条没有名字"。
  已加 text_colour_for()：近黑色改白；同一行本帧已经用白色画过则丢弃这次(重复层)。
- 测试脚本：tap_script 用帧缓冲像素，1080p 下 开始游戏=960,919 存档位=959,279；走到 NPC/剧情约需 render 3200-3700 帧。
