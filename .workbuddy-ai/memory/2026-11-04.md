# 2026-11-04 (下午) 三个用户报障的定位与修复

## 1. 剧情对话白字被金色块盖住 —— 根因找到并修复

之前几轮把 GL 绘制路径全排除了，方向错了：那块东西不是"新画的一层"，而是**引擎自己那个字符串图像 quad，内容全是垃圾**。

链路：
- 打字机效果走 `GRPX_DrawSubStringWithFont2` → 我们 `nx_sub_string` 用 FreeType 画白字（正常）。
- 一行打完时引擎调 `SGL_grpCreateStringImageInRect`：先 `glTexImage2D(GL_ALPHA, w, h)`，
  再 `glTexSubImage2D(GL_ALPHA)` 上传"光栅化结果"。而 `SGL_RenderFontToAlphaImageInRect` 是 no-op，
  所以上传的是**未初始化堆内存**；我们的 `expand_alpha_to_rgba` 把垃圾原样搬进 RGBA 图集。
- 图集被画成一个 quad，正好压在白字上 → 约 250x65（1080p）的"金色花纹"。
  尺寸对得上：日志里 csir 的图集就是 256x32，放大 2 倍画出来。
- 12:05 那版"延迟填充、留空"只跳过了**我们的**填充，引擎的垃圾上传依旧走 expand 路径，所以块还在。

修复（src/main.c）：
- 新增 `g_stratlas[]` 登记 csir 分配的图集（`stratlas_add`），纹理 id 被别的纹理复用时 `stratlas_drop` 注销。
- `nx_glTexImage2D` 的 csir 分支：不再把引擎的 A8 指针当 RGBA 读（那是 4 倍越界读），改用 calloc 的零缓冲。
- `nx_glTexSubImage2D` 的 A8 分支：命中 stratlas 就上传全零，不再 expand 引擎垃圾。
- 我们自己 `strimg_fill` 走的是 GL_RGBA 上传，不受影响 —— 真正没有其它绘制者的行仍然会被填。

## 2. 新建存档选同一职业会读旧档 —— 找到判定点

`STATE_EnterGame`（0x1ef1dc）:
```
ldr x8,[0x29f928]   ; &GAMESTATE_bNewGame (0x2d48d8)
ldrb w8,[x8]; cbz w8, done     ; 标志为 0 时整段新角色创建被跳过
... GAME_StartNewGame(slot, class, ...)
```
标志为 0 时游戏界面就会去读卡上已有的存档。标志由 `SaveSlot_SlotButtonExe` 写：
空槽分支写 1，**有存档分支写 0**。所以只要在职业界面和"开始"按钮之间有任何一次
落到存档行的点击（弹层/触摸穿透），标志就被清 0，新角色不创建，回到旧角色。

修复：`SelectCharacter_StartGame` 和 `SelectCharacter_ButtonStartExe` 包装里强制
`GAMESTATE_bNewGame = 1`（该按钮只在新建流程出现，读档流程不会进职业界面，安全）。
日志 `flow: ... new-game flag N -> 1` 会打印原值，若原值真是 0 就验证了这条链路。

## 3. 槽位 3 死档删不掉 —— 已知的第三个垃圾桶被弹窗盖住

`src/main.c` 里原有注释记着：第三行垃圾桶 (848,466 66x66) 被一个未应答消息框的
OK 按钮 (726,470 300x92) 盖住，点击被引擎交给那个 OK，**删除确认框根本不会创建**。
之前的绕法（直接调 `SaveSlot_SlotButtonDelExe`）副作用是把引擎"当前存档槽"指针留在槽 3，
导致之后所有自动存档都写进槽 3，已被移除。所以这个 bug 一直挂着。

本次修复（不碰引擎的当前槽指针）：
- `note_bin_tap` 记录点击前的弹窗队列深度和命中的 bin 控件；`delete_fallback_tick`（主循环里跑）
  在 12 帧后发现没有新弹窗 → 认定点击被吞 → 直接调用引擎自己的 `SaveSlot_SlotButtonDelExe(ctl)`，
  真正的"是/否"确认框由引擎弹出，槽号由引擎自己算（不猜）。
  调用前后把引擎的"当前存档槽"指针 (`*(engine+0x29f920)`) 存下来再写回，抵消 `SAVE_GetSaveSlot()`
  的副作用（这正是当初"槽 1 的新档跑到槽 3"的原因）。
- 启动时 `drop_orphan_checkslots`：没有对应 `save<N>.dat` 的 `thpcheckslot<N+1>.dat`
  改名为 `.orphan`。引擎删档只删数据文件、留下 checkslot，这种半残状态正是"死档"的样子。
- 确认删除时把仍存在的 save*.dat 打进日志，用来区分"对话框弹了但没删掉"和"对话框没弹"。

### 槽位编号的坑（尚未定论，别再猜）
引擎里 bin 的 child index 直接用（0..2 = 上中下），行按钮用 index-3。
但 14:10 那次日志里，点最下面一行 (544,424) 读的是 thpcheckslot1 + save0（= 槽 0）。
两者对不上，所以在没实测确认前**不要**用"屏幕行号 → save<N>.dat"的映射去删文件，
本次改成让引擎自己算槽号。
