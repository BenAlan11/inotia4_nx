## 真机"进度条跑完就报错闪退"的根因（已修）

crash report（`sdmc:/atmosphere/crash_reports/`）里：Data Abort，FAR=0x44，
PC 在 `j_CallBooleanMethodA` → `read_jvalues`。

反汇编确认 `add x0, x2, #0x44`（`FakeID.sig` 的偏移），x2 = 0 —— **引擎传了
NULL 的 jmethodID**。AT 0x44 读空指针。

修法：`jni_fake.c` 加 `id_safe()` + `ID_SAFE(id)` 宏，批量插到 17 个
`j_CallXxx` / `j_NewObject` 入口；坏 id 退化成 `id_unknown`（name "unknown"），
打印一次 caller。**所有 JNI 方法入口都必须过这一道，否则一个空 id 就是一次
2168-0002。**

## 重大发现：libnx 的 `glColor4x` 不生效（已修）

`glColor4x` 直接映射到 libnx 后，**current color 永远是 (1,1,1,1) 白色**，
引擎设的定点颜色（尤其是 alpha）被丢掉。后果是所有淡入淡出/遮罩/染色
quad 都画成不透明白色或全黑。

修法：`nx_glColor4x()` 自己转 float 再调 `glColor4f`：

```c
glColor4f(r/65536.0f, g/65536.0f, b/65536.0f, a/65536.0f);
```

## 触摸链路全打通，定位到"控件树里没有槽位控件"

hook 链（全走 GOT 覆写，都生效）：注入 → handleCletEvent_MV →
handleCletEvent → `TouchHandle_Event(root, code, coord_obj, 0)` →
`ControlObject_EventProc(root, 0x17/0x18, data, 0)`。

发现：
1. **Hive 弹框 CANCEL 后 `InputLayer_GetRoot()`（全局 0x2b4000+0x140）被
   置 NULL**，之后所有点击命中直接失败 → 加了 last_good_root 恢复补丁。
2. **`UIPopupMsg_Free()` 是帮倒忙的**——调用它之后 root 更是回不来；
   禁用 Free 后引擎自己会挂新树（root 出现新地址 0x210ac0a43c）。保持禁用。
3. 禁用 Free 后点击时 CO_EP 只遍历到 **4 个控件**
   （0x210ac1843c/18534/1862c/18724，间隔 0xE8，疑似弹框残留控件），

4. `TouchHandle_Event` 里的 press 分支有个对 [0x2b2000+0xeb0] 的自旋等待

注意脚本里 section 解包字段顺序是
`<IIQQQQI`（name,type,flags,addr,offset,size,link），sec 值为 (addr,off,size)。

## 11/01 18:xx 回滚事故 + 真机闪退 + 卡死复现（本轮）

### 1. 真机"打不开就闪退"的根因（已修）
`patch_bl_callsites()`（17:38 加的实验代码）在 `so_finalize()` **之前**就读写
`game_mod.load_virtbase + 0x11ee20`。`load_virtbase` 此时只是 `virtmemFindCodeMemory`
的**保留区，尚未映射**（映射发生在 `so_finalize` 的 `svcMapProcessCodeMemory`），
真机上一读就 Data Abort。Eden 那块内存恰好可读，所以只在真机炸。
修法：扫描/改写走 **staging 副本 `load_base`**，地址比较仍用 `load_virtbase`（BL 是
PC 相对，按运行时地址算）；去掉 `svcSetMemoryPermission`；整体用 `patch_http` 开关
默认关闭（静态扫描证实 `HttpMakeDataReqSaveData` 在 .text 里 **0 个 BL 调用点**，
只走 PLT，这个 patch 本来就没用）。

`iconf.inject` 覆盖成 0 → **所有触摸注入直接 return**。config.ini 里没写
`inject` 时就是"整个界面点不动"。已修，config.h 里被挤成一行的注释也整理了。

### 5. 工具经验（省时间）
- PLT 桩 = `adrp x16` + `ldr x17,[x16,#imm]` + `add x16` + `br x17`；**ldr 的 imm 要 ×8**，
  否则 GOT 地址全错（一开始 3236 个桩只解析出 1 个）。
- capstone 的 `adrp` 立即数文本带 `#`，`int(imm,16)` 会抛异常。
- `virtbase = 符号运行时地址 - st_value`（日志里 `flow:` 行给出运行时地址，可直接反推）。

### 8. 「存档页点了没反应」的真正原因（已修，Eden 验证）

现象两段：
- Free 开着（延迟 30 帧）→ 点槽位**变红但随后卡死**
- Free 跳过 → 点槽位**完全没反应**

日志给出一行决定性证据：

```
ui: TouchHandle_Event root 0x210ac1843c (live 0x210ab2b7d4, 1 children)
```

引擎把触摸**发给了一个陈旧 root**（只有 1 个子控件 = Hive 弹框残留的 id 30 空壳），
而 `InputLayer_GetRoot()`（0x2b4140）里是真正的存档页树（6 个子控件 / 26 个控件）。
所以每次点击都在那个空壳里做命中测试，全返回 0 → 界面完全没反应。

**修法**（`nx_TouchHandle_Event`）：只要 `live` 存在且 `live != root`，就用 `live`。
验证：加上后立刻出现 `ui: event root ... is stale, using live ...`，紧接着
`flow: > UI_SetPopupProcessInfo(4,0)` —— 点槽位有反应了。

其它同批修改：
- 弹框应答改为**同帧**校验后 Free（`popup_base_real() == ctl` 才 Free），不再延迟 30 帧；
  实测 CancelExe 已经把全局清空，所以多数情况下直接跳过。
- 应答后再调 `TouchHandle_DeleteControl(ctl)`（引擎自己的出树接口）。
- `touch_state_guard` 收敛：只在 touch count==0 且 120 帧后清 **moving**，
  不再清 selected（selected 被清会让 DeleteControl 失效）。
- `shim_connect()`：菜单就绪后 connect 立刻返回 ENETUNREACH（真机无网时原来会阻塞很久）。

⚠️ 排查用的两个坑：
- `TouchHandle_Event` 的 coord 是 **64 位 x / 64 位 y**（+0 是 x，+8 是 y），
  按 +4 读 y 永远是 0，我因此误判过一轮。
- `CO_EP` 日志上限 100 行会截断遍历，看不清到底有没有遍历到槽位；已放宽到 400 并带 id/rect。

### 14. 字体：把 Java 字体表填上（22:3x，关键进展）
