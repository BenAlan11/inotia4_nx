## 10:25 NPC 名牌：真正的调用链与两个根因

### 上一轮判断错的点
`INSTANTMSG_DrawNPCName`（软件 GRP 版）**不是**游戏实际走的路径。
`INSTANTMSG_Draw` 的 switch 里，名牌分支直接调
`INSTANTMSGPorting_DrawNameFrame`，也就是 GL 版：

```
INSTANTMSG_Draw
  GRPX_GetColorFromGRP / GRPX_SetFontColor          ← 名字颜色（pen colour）
  GRPX_FillRectRGBAlpha(0, 49, screenW, fontH+8, 0,0,0, 70)   ← 背板黑条
  GRPX_DrawStringWithFont(str, W/2+1, 54, 2, 1)     ← 阴影
  GRPX_DrawStringWithFont(str, W/2,   53, 2, 1)     ← 名字
```

`GRPX_DrawStringWithFont` 早就是我们的 `nx_grpx_draw_string` —— 字**一直在画**，
只是画成黑色：`SGL_grpFillRect`（FillRectRGBAlpha 的实现）结尾
`glColor4x(0,0,0,0.7)` 且不还原，我们却用 `glGetFloatv(GL_CURRENT_COLOR)`
取色 → 黑底黑字。

### 根因 1：文字颜色（无字）
引擎真正的文字颜色在 SGL context（`SGL_grpFontColor(r,g,b)` /
`SGL_grpFontAlpha(a)` → `SGL_Context::SetColor/SetAlpha`，字段 +0x44/+0x48/+0x4c/+0x50）。
新增 override 记录 pen 颜色，`pen_colour()` 在"引擎刚设过"时优先用它，
否则回落到 GL 颜色（其它界面已验证过，不动）。

### 根因 2：白条闪烁（抽搐闪动）
`nx_glDrawArrays` 里"把近黑色文字 tint 提亮成白色"的规则只判了
`is_filled_atlas(当前绑定纹理)`，没判 `GL_TEXTURE_2D` 是否开启。
关闭纹理时绑定 id 仍留着上一次的，碰上我们的字符串图集就会把**任何**
4 顶点无纹理 quad 刷成白色 —— 名牌背板正是这种 quad（黑 70%），
于是背板在黑白之间跳，就是玩家看到的"抽搐闪动"。
修法：`&& glIsEnabled(GL_TEXTURE_2D)`。

## 11:20 整屏抽搐闪烁：文字绘制器的两处 GL 状态泄漏

用户澄清："整个画面闪烁，不止名牌位置"。查下来是 `draw_quad()` 泄漏了引擎依赖的状态：

1. **投影矩阵栈溢出**：`glPushMatrix` 到 GL_PROJECTION。GLES1 只保证 **2** 层，
   而 `pact2DBegin` 已经占了一层 → push 被丢弃，`glLoadIdentity` 覆盖了引擎的
   2D 投影，`glPopMatrix` 又弹掉了引擎那一层 → 该帧后续全部用单位投影绘制，
   下一帧又正常 = 整屏抽搐。改为 `glGetFloatv` 保存 / `glLoadMatrixf` 还原。
2. **顶点指针悬垂**：quad 的顶点数组是 `draw_quad()` 的栈变量；引擎的 SGL GRP
   绘制（`SGL_grpFillRect`，名牌背板就是它）用一块全局数组提交、**不重新指定
   pointer** → 读到我们那个已失效的栈帧 = 随机坐标的 4 顶点黑色 70% quad，
   可以糊满整屏。新增 `nx_restore_client_arrays()`（main.c），`draw_quad()` 收尾时调用。
3. 附带修正：pen 颜色只在 **GL 颜色接近黑色**（填充留下的）时才替换，
   否则会污染 HUD 药水数字（变土黄）和角色选择页职业名（变黑）；
   `SGL_grpFontAlpha` 不再算作"引擎刚设了颜色"。

产物：`build/inotia4_nx.nro` md5 `4dbe6a16411006a246aea59953480f70`（11:13:29），
已同步 dist 与 Eden sdmc；config.ini 已清掉 tap_script/shot，log_level=2 留给用户手动测试。

- jni_fake 里答 `marketConnect` → 回调 `(0,"google",6,&code)`；

### 硬墙：商店状态机是服务器驱动的
- `NetworkStore_Process` 按 state 1..13 跳转（跳表 `0xbd192`）；
  state 1 → `Network_SendData(0x42, -1)`（发请求），state 4 才画列表。

- 强制 `NetworkStore_SetState(4)` + `Network_SetProcessType(1)` 无效：
  `[0x2d8508]`（received item list）是 NULL，页面控件由
  `Scene_Init_POPUP_SC_INAPP_{GEMSHOP,GOODS,WEAPON,PACKAGE,HOT,ARMOR}`
  → `NetworkStore_InitializeMenuData` 构建，而它们没被 push。
- 结论：离线进商店 = 伪造 opcode 0x42 的服务器回包（协议逆向），
  不是一两个 flag 能解决的。

## 14:55 字号改用引擎的 font index（不再按像素猜）
`GRPX_DrawStringWithFont(text, x, y, align, font_index)` 的第 5 个参数就是引擎给的字号：

## 19:09 任务弹窗排版定稿（known-good-20261105-1909）

## 23:45 技能说明页滚动：现状与结论（未完成）

### 已经查清的事实
- 页面结构：`UIDesc_DrawTextScroll(ctrl, scroll)` 在 `rect.y + scroll` 画当前等级块，
  再在 `+ ctrl->height + 20` 画虚线，然后画下一等级块；最后还有一个**数值对比块**
  （`40 ▶ 40`、`210.5% ▶ 230.5%`）——它**不经过** `X_TEXTCTRL_DrawTextControl`，
  是引擎用字符串图集（atlas quad）画的，文本永远到不了我们的绘制层。
- 文本控件 `+0x08`（高度）在本移植里是 0，导致所有区块叠在一起；
  按折行行数写入后区块才分开（`nx_textctrl_set`，只对宽度 ≤420 的控件）。
- 说明页滚动控件：`active=32`（满足 `UIDesc_Process` 的条件）、`content 519 > viewport 298`
  （有滚动范围）、绝对矩形 `(645,193,358,357)`（命中区域正确），
  但**拖拽事件到不了它**——`ControlScroll_Process` 内部的位置 `data+0x50` 始终为 0。
  左侧技能树的滚动控件能正常拖，两者差别在控件树/事件层，未查明。
- `ControlScroll_Scroll` 的模型：位置在 `data+0x50`（负=向下），
  有目标控件（`data+0xe0`）时会把位置应用到目标控件——写它会自我反馈导致无限滚动。
- 自绘滚动滑块（`text_fill_rect`）会破坏引擎后续绘制（顶点指针/GL 状态），
  表现为满屏重影；已删除。写 `data+0x50`（无目标控件时）可让引擎的滑块跟随，已验证可用。
