## 12:20 技能说明页：滚动恢复 + 版面重排 + 长文本截断（known-good-20261106-1213）

### 1. 滚动：把手指位移喂给引擎自己的滚动控件
- 说明页的滚动控件 `[virtbase+0x2b5a30]`（`UIDesc_ResetSkillScrollControlRect` 建的），
  `ControlScroll_Draw` 会把 `data+0x50`（位置）作为第二个参数传给绘制回调。
- 但它的 `ControlScroll_ControlEventProc` 在移植里永远收不到指针（该控件只能走控件树虚分发，
  左侧技能树是 `ControlSkill_ControlEventProc` 直接调 `ControlScroll_EventProcPressed`，
  所以树能拖、说明页不能）。
- 修法：`input.c` 记录按下落点（`input_drag_start`）+ 每帧位移（`input_take_drag_dy`），
  `desc_scroll_tick()`（主循环里 input_update 之后）把位移按引擎单位换算后累加到 `data+0x50`，
  钳制 `[view-content, 0]`。只有落点在滚动控件矩形内才生效，所以拖左边树不会带动右边。
- 引擎随后自己完成一切：文字、虚线、对比块、滚动条全部按同一个偏移走。

### 2. 版面：把 UIDesc_DrawTextScroll 换成我们自己的文本流
引擎原逻辑（反汇编 0x145c94）：
```
A  rect.y+scroll            ctrlA=0x2b4a38, 高度 [0x2b4a40]
-- 虚线 A.y+A.h+10
B  A.y+A.h+20               ctrlB=0x2b5230, 高度 [0x2b5238]
-- 对比块 B.y+B.h+5         UISkill_DrawDescAbility
```
这些高度来自 Java 光栅器生成的字符串图，移植里是 0 → 三块叠在一起。
现在 `data+0xa0`（滚动控件的绘制回调）被强制指向我们的 `nx_desc_text_scroll()`：
A、虚线、B 全部由 `text_draw_engine` 自己画（同一套折行/行高），
对比块仍交给引擎的 `UISkill_DrawDescAbility(path, x, y, w, fontH+4)`，只是起始 y 由我们给。
实测日志：`A y193 h200 | dash 403 | B y413 h75 | ability 493`（视口 645,193 358x298）。

### 3. 七行空行：text_draw_engine 的折行下压累加器
`text_draw_engine` 有个 `wrap_extra`：为"引擎逐行送一行、我们折成多行"的提示条设计，
画完多行后会把引擎的下一行整体下推。说明页是整段一次画，A 块 8 行 → 记 7×25=175px，
紧接着画 B 块就整体下移 7 行，正好压在对比块上。
修法：整段绘制前后 `text_set_wrap_extra(0)` / 恢复 `1`。

### 4. 长文本被截断：256 字节缓冲 + 拿框宽当字节数
`X_TEXTCTRL_SetTextControl(ctrl, str, width, ...)` 第三个参数是**框宽 358**，不是字节数，
但 `tctrl_store()` 用它做拷贝上限，且缓冲只有 256 字节。
技能说明整段约 269 字节，尾部 `： $S5秒$B`（蓝色 5 秒）正好被切掉。
修法：缓冲 256 → 1024，拷贝长度按 `strlen()`。
顺带修好所有超过 256 字节的文本控件（物品/任务说明尾部）。

## 12:40 说明面板的两个按钮 + 技能点数值配色

### 1. `技能点: 0` 的 0 发暗
引擎把这行拆两次画：标签 `技能点:` 在 `(610,147)`（金色规则），数值 `0` 在 `(677,147)`。
移植里数值提白靠 `is_stat_value()`，它的判定带下限写的是 **y >= 150**，这行正好 y=147 →
落到引擎传来的 `0x684f30`（暗棕，因为 UI 调色板在这里全 0）→ 在深色底板上看不清。
修法：下限 150 → 140。标签仍走金色规则，保持"标签金、数值白"。
⚠️ 中途试过"整条标题栏 y130..190 一律画白"，把**角色页**右上角那块金字也刷白了，已撤掉。

### 2. `学习` / `取消快捷键` / 物品页右侧按钮点不动 —— 分发顺序问题
`ControlObject_EventProc` 按子控件链表顺序递归，返回 1/2 就停。该窗口的子树：
```
id 99   (625,133) 409x431   说明面板（滚动视口 + 两个按钮）  ← 排在后面
id 100  ( 88,133) 1137x431  左边大内容面板，矩形＝整窗       ← 排在前面
```
`100` 先被走：按下点没落在任何格子里 → 返回 0 → 链表到头 → `99` **永远不会被访问**。
所以说明面板里的一切（含按钮）都收不到事件；只有滚动视口能滚，因为那是我们自己驱动的。
修法：已有的 `nx_ControlObject_EventProc` 钩子里，整次分发（`colevent_depth == 1`）
返回 0 时，若落点在说明面板矩形内、且**不在滚动视口内**（`645..1003 x 193..493`），
手动把 0x17/0x18/0x19 转给面板（`colevent_real(dp, ...)`）。
视口必须排除，否则引擎拖动与我们自己的滚动叠加成双倍速。
日志实证：`ui: desc panel 0x... rect 625,133 409x431 forwarded code 0017 at (900,524) -> 1`。
物品页同理（面板矩形 `173,133 409x431`，转发点 `390,526`）。

## 19:05 对话名字金色 / 心里话灰 / 存档地图金（当前默认）

### 1. 说话人名字的金色：改成"关系判定"而不是 y 带
`is_gold_text()` 原来要求名字落在 **y 425..445**。那只是**带立绘的竖版**对话框
（名字 434、正文 487）。底部横条版式把同一对放在 **527 / 574**，所以
`黑暗教团士兵`、`贝勒塞士兵` 只拿到名字字体（变大）而没拿到金色，而 `凯恩`、`卓拉德`
走的是竖版所以是金的。
新规则：**字体 index 2（名字字体）画出的字符串，且本帧或上一帧有正文行落在它下方
0..160 px**。角色页自己的名字下面没有正文，地图名横幅同理，都不会误判。

### 2. 括号里的心里话 → 灰
对话区（y >= 400）首字符是 `（`(U+FF08) 或 `(` 的行，颜色改 `0xAAAAAA`。
实测原版同一块底板上：正文 `#E7..`、想法 `#A4..`。

### 3. 存档页地图名 → #C6B992
`is_gold_text()` 现在返回"哪种金"，而不是让调用点自己再推一遍：
