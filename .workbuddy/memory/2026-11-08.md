  因为这条路径根本不查那张表。

### 真因（反汇编实锤）
- 剧情/角色介绍正文走 `TEXTCTRL2_*`，不是 `X_TEXTCTRL_*`：
  - `GRPX_DrawSubStringWithFont2` (0x1223a4) 只有 3 个调用点，全在
    `TEXTCTRL2_DrawAsStep` (0x1daf98) / `TEXTCTRL2_Draw` (0x1db03c)。
  - `TEXTCTRL2_LineProcess` (0x1da778) 把 `$X` **消费成 display unit 的
    颜色字段**（unit 32 字节，`+8` 是颜色），不写回字符串缓冲。
  - `TEXTCTRL2_Draw` 循环：`ldr w0,[x26,#8]` → `GRPX_GetColorFromGRP`
    (0x1227a0, 输出 `0xFFBBGGRR`) → `GRPX_SetFontColor` (0x122848)
    → `GRPX_DrawSubStringWithFont2(原文+unit.offset, unit.len, ...)`。
  - 所以我们的 hook 拿到的是**剥码的 span 视图**（码在 offset 窗口外），
    颜色只在 `GRPX_SetFontColor` 的参数里。
- 移植层 `nx_sub_string` 一直用 `glGetFloatv(GL_CURRENT_COLOR)` 取色 →
  恒白。这是确定性缺陷，与 `$` 码是否存在无关。
- 格式印证：`tctrl_colour()` 注释已写明 `GRPX_SetFontColor` 参数是
  `(a<<24)|(b<<16)|(g<<8)|r`，用 `__builtin_bswap32()` 转 `0xRRGGBBAA`。

### 改法（只改 main.c）
- 新增 `nx_grpx_set_font_color()` hook，加入 override 表；记录 w0，仅当
  返回地址落在 `T2_DRAW_LO..HI` (0x1daf98..0x1db288) 时；**所有调用者
  都转发给原函数**（`grp_set_font_color_real` 用 `so_try_find_addr_rx`
  解析；`so_set_overrides` 只登记集合、不改符号表，不会拿到自己的 hook）。
- `nx_sub_string`：同帧有 span 颜色时 `color = __builtin_bswap32(w0)`，
  否则回退 GL_CURRENT_COLOR；`text_colour()` 仍把不透明黑 `$B` 提为白，
  所以普通行保持白、只有强调 span 变彩色。每个 span 一次回调 = 一行
