## 23:18 真正根因与根治（推翻上面"Hub 网络错"的猜测）

用户两次纠正：不是弹窗，是**存档条目本身变成 ERROR(00)**；并明确
"现有存档不要了，确保之后不会再出现这个问题就行"。

**不是密钥错，是存档文件尾部残留**（用引擎算法 + 真实文件硬验证）：
- 复现 `ENCRYPT_Process2`（表在 libgame.so vaddr `0xbb7e8`）：
  nonce = data[len+1]，`key[(nonce+i) % keylen]`（**索引不截断 8 位**）
  + `TBL[(nonce+i)&0xff]`，与密文 XOR；
  `data[len]` = 密文和 &0xff，`data[len+2]` = 明文和 &0xff。
- `inotia4-switch-save-v1` 解 `thpcheckslot1.dat` →
  `2|011110|99|99|99|99|99|END|`，双校验和全过 → 密钥正确。
- `save0.dat` 3426 B：`sumcipher(3423)=228` 但 `data[3423]=25` → 长度错位。
  内部 `L=3361` 的块用同密钥解出合法存档数据、双校验和全过
  （明文头 `7f 05 40 05...`，与 `.deleted` 里 `ff ff ff ff...` 同构）。
  尾部多 62 字节残留 → 引擎按 `filesize-3=3423` 解密 → 校验失败 →
  槽位画 `ERROR(00)`。历史上的 `save*.dat.bad` 是同一个 bug。

**根因 = bionic / newlib 的 open flag 位不兼容**：
- 引擎 `SAVE_SaveDataAsNameAndKey` → `CS_fsOpen(mode 4)` →
  `open(path, 0x241, 0x180)`，bionic `O_WRONLY|O_CREAT|O_TRUNC`，
  其中 **bionic O_TRUNC = 0x200**。
- 移植层 `shim_open()` 原样把 flags 交给 newlib `open()`：
  **newlib 0x200 = O_CREAT，O_TRUNC = 0x400**（见
  `tools/dkp_rootfs/.../sys/_default_fcntl.h`）。
  于是写存档**从不截断**；新档比旧档短时旧尾部保留。
- 注意：这解释了"今天修改前还能打开"——与今天改动无关，是长期潜伏，
  只是恰好某次存档变短才暴露。也解释了 `连接出错。请稍后`（离线 Hub）
  只是读档失败后的连带弹窗，不是原因。

**三层修复（都未改任何现有存档文件）**：
1. `src/libc_shim.c` 新增 `bionic_flags_to_newlib()`，在 `shim_open()`
   里翻译全部 bionic 位（CREAT 0x40→0x200 / EXCL 0x80→0x800 /
   NOCTTY 0x100→0x8000 / TRUNC 0x200→0x400 / APPEND 0x400→0x8 /
   NONBLOCK 0x800→0x4000），高位透传；`shim_open` 只挂引擎 import 表，
   移植层自己的 `open()` 不受影响。**这层是根治。**
2. `src/main.c` 新增 `save_full_path / save_scan_valid_len / save_trim_to`；
   `nx_save_nk()` 写后若文件偏长就用 `"wb"` 重写精确 `len+3` 字节
   （`ftruncate` 在 Switch devoptab 上不一定可用，故用 `"wb"`）。
3. `nx_load_nk()` 读失败时用**引擎自己的 `encrypt_real`** 扫描最长合法 L，
   守卫 `L>=64 && L+3<n && (n-L-3)<L/2`，裁掉残留尾后重读一次；

- `input.h`：`NavItem` 加 `tx/ty`（推荐注入点）与 `shape`；新增
  `NAV_PAGE_*` / `NAV_K_TITLE_* / SAVE_ROW / CLASS / START`；
  `input_set_nav()` 增加 `page_kind` + `back` 两个参数。
- `main.c` `nav_scan()` 重写：`nav_find_pages()` 收全屏层 →
  `nav_sig()` 按子控件尺寸打分 → `nav_page_kind_of()` → 取最后一个。
  三页用 `nav_collect_page()` 按控件语义收集（排除删除 bin，防误删存档）。
- `input.c`：三页直接进 BODY、只用十字键 + A/B；L/R 完全不响应；B tap 本页
  返回箭头；模态确认框（`popup_on()` / `ui_confirm_button()`）在 A/B 边沿
  优先接管，保住之前修好的「路障」确认。
- 职业页两段确认：`NAV_K_CLASS` 上按 A → tap 该徽章 + `nav_class_pick=1` +
  `nav_idx` 指向 `NAV_K_START`；再按 A 才进游戏。`nav_pick_initial()` 在
  4 帧重扫后仍把光标保持在 START。
- ⚠️ 职业页下方两个徽章 `(286,313)/(736,313)` 中心落在底下存档行
  `(251,256 634x150)` 内，`nx_TouchHandle_Event` 会把落在 save row / bin 的

  调到 407，正好在 row2 结束 406 与 row3 开始 422 的缝里）。不改引擎事件链。
