## 导航「光标跑到看不见的控件」第三轮修正
用户连续两轮反馈「弹框时仍会到背后被遮挡的框移动」。前两轮都在猜绘制层级，这轮
改成直接用日志里的真实控件树定量验证，找到真正的漏网之鱼。

- **日志证据**（11-10 17:30 那轮，snapshot 30/32）：物品页 `nav: page up ... 32 controls`，
  清单里前三项是 `(505,216 125x55)`、`(403,516 150x55)`、`(583,516 150x55)`。
  它们属于一个 `360,108 416x443` 的弹窗层，而该层挂在**第二个 `1137x640` 全屏容器**
  里（页面层是第一个）。用户截图里根本没有这个弹窗，所以光标能停在三个隐形按钮上。
- 之前 `nav_gather_boxes()` 主动跳过了 `w>=1100 || h>=600` 的全屏层，导致这一层永远
  不参与遮挡判定。现在改为全屏层也记录。
- **把页面容器本身作为 depth = -1 的 box 放入比较表**：任何与它完全同 rect 的子层
  （`1137x640`）判为 hidden，连带其整棵子树（那三个按钮）一起排除。
  离线模拟：snapshot 30/32 的 items 32 → 29，hidden 从 1 → 2（新增 id 134 = 残留弹窗层），
  剩下的 29 个全部是可见控件（浮层关闭 X 1 + 三个动作按钮 3 + 左列 3 + 物品格 16 + 背包 6）。
  snapshot 33/34（详情弹框态）11/13 个不变，没有误伤。
- 另加「围栏」方案 `nav_find_fence()` / `nav_inside_fence()`：用
  `p_ctrl_proc(c) == ctrl_scroll_proc`（ControlScroll_EventProc, vaddr 0x14d440）找
  最前面的说明/详情浮层，凡**完全落在它 rect 内、且不属于它子树**的控件一律排除。
  这是纯矩形包含测试，不依赖绘制顺序猜测；目前在这批 snapshot 上是双保险（同 rect
  判定已先命中），留给后续页面用。
- `nav_collect_items()` 加 `inside` 参数传递「是否处于浮层子树内」。
- 诊断日志增强：`nav: page ... (N panels, N hidden, fence x,y wxh)` + 逐项
  `nav:   [i] x,y wxh kind k` 清单（items 数变化时打印）。以后再出「看不见的地方」，
  直接读日志就能定位，不必再猜。

## 22:0x 第四轮：可操作控件按 proc 判定 + A/Y 分工
用户反馈：「已到（遮挡问题解决），有些不是操作的控件也被识别为操作控件了。另外，
我是希望游戏中攻击和地图中的交互绑定 Y，剧情对话这些还是按 A 推进」。

- **符号表是判据**（`tools/elfinfo.py` 解析 `data/libgame.so` exports）：
  `0x130514 ControlObject_DefaultPressKey`（容器，无自己的点击）、
  `0x13ddf4 ControlButton_EventProc`（按钮）、
  `0x13e36c ControlItem_EventProc`（物品/技能/背包格）、
  `0x13e72c ControlScroll_EventProc`（滚动视口）、
  `0x1499e0 UIEquip_CharacterEvent`（角色立绘，不是按钮）、
  `0x14d440 UIGameMenu_SubEvent`（详情/说明面板）、
  `0x15a3f0 UIPlay_SkillEventProc`（快捷槽）、
  `0x15a7c4 UIPlay_VirtualEventProc`（HUD 摇杆/攻击盘）。
- 新增 `ctrl_item_proc / ctrl_skill_proc / ctrl_menu_sub_proc`（`so_try_find_addr_rx`
  按名字取，绝不硬编码地址）与 `nav_is_actionable()`：**只有 ControlButton /
  ControlItem / UIPlay_SkillEventProc 能进导航列表**。离线用 snapshot 16 验证：
  `103,362 377x55` 容器条、`302,243 157x157` 角色立绘被过滤，按钮与格子全保留。
  符号取不到时回退旧行为。
- **移除了上一轮的 fence**：它拿 `ControlScroll_EventProc` 找详情面板，找错了符号
  （详情面板是 `UIGameMenu_SubEvent`），所以日志里 fence 一直是 `-1,-1 -1x-1`，
  从未生效。遮挡仍由已验证有效的「同 rect 层叠 + 页面容器 depth -1」负责。
- **A/Y 分工**（`input.c:hud_update`）：Y = `HUD_BTN_ACTION`（攻击 + 地图交互），
  A = 消息框 `popup_press` / 设置页确认；地图上 A 原本什么都不做。新增
  `ui_dialog_button()`（main.c，遍历 root 找全屏 `ControlButton_EventProc`）+
  在 `AB_MAP` 分支用 A 的按下沿 tap 它推进剧情对话。日志验证该全屏按钮只出现在
  snapshot 5-12（教学/剧情对话阶段），普通地图 13 之后完全没有 → A 不会变成
  地图交互。日志标记 `input: A advances story dialogue at (...)`。
