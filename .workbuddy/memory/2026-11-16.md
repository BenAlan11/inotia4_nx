## 18:56 用户提议「逻辑 tick 固定 16/17 FPS + 渲染提 30/60 FPS」——判定不可行

用户设想引擎里有可分离的 Update()/Render()，想给 Update 加真实时间累加器，
只把渲染频率提上去，得到「画面顺滑但游戏速度不变」。做了完整静态反汇编，
结论是**该引擎没有独立的 Render 入口，逻辑与绘制是 1:1 绑定的**，而且
11-14 晚上已经把这条路走过一遍并整体回退。

### 调用链（本次反汇编实证）
- `Java_..._nativeProcess` @0x25ae00 只有 24 字节，三个调用：
  `jProcessEvent` → `TM_Run` → tail `ThreadProc`（用 `tools/plt.py` 解析
  0x2975b0/0x297790/0x2977a0 得到）。
- `TM_Run` @0x25e664 是定时器队列：遍历链表，用 `CS_knlCurrentTime` 判断到期，
  到期则 `blr` 回调，回调里 `sdiv/msub` 重算下次时间。
- `MainProcess` @0x169494 是那个回调，248 字节：
  `CS_knlCurrentTime` → `UI_PopupProcess` → `STATE_NextStartProcess` →
  `UIPopupMsg_Process` / `POPUPSTATE_Process` → `SOUNDSYSTEM_Process`，
  结尾 `x21 = now + w22`（`w22` = 全局 u16 帧周期，即 APPINFO_nTimer），
  再用 `CS_knlSetTimer` 排下一帧，`x1 = max(deadline - now2, 10)`。
  → **引擎原生就有「基于真实时间的固定步长」**，不需要移植层再加累加器。
- `CS_knlSetTimer` @0x24d760 → `TM_Set`；`CS_knlCurrentTime` @0x24d77c →
  `gettimeofday`（我们的 `shim_gettimeofday`），毫秒 + 全局基准。
- 绘制：`jRequestRender` @0x255524 的三个调用者分别是
  `CSOGL_grpFlushLcd` / `CSFB_grpFlushLcd` / `SGL_Flush_Android_GL11`
  （`tools/find_callers_sym.py`），即「画完一帧 → FlushLcd → requestRender」。
  移植层只在 `jni_take_render_request() > 0` 时 `egl_swap()`。
- 我们的 `while (appletMainLoop())` 已经是 60 Hz（`budget = freq/60`），
  它只是在**轮询定时器**，不驱动逻辑也不产生画面。

### 硬性证据：渲染与逻辑 1:1
- 11-14 23:4x 实测：Eden 基线 loop 59 / draw 19 fps；
  把 `APPINFO_nTimer` 改成 16ms 后 **loop 59 / draw 59 fps**（用户截图确认）。
  若存在独立 Render，draw fps 不会随 tick 周期变；它变了 ⇒ 每 tick 恰好画一帧。
- 引擎**按帧计数推进**：两轮开场淡入 alpha 序列逐帧完全一致
  （1.00→0.94→…→0.07，每帧固定 -0.067），没有按 wall clock 插值。
  所以在两个逻辑 tick 之间重复绘制只会得到**逐像素相同的帧**，
  不会产生「视觉平滑化」，只是白烧 GPU。
- 现有日志 `requestRender` 实测 143 样本：平均 49.3 ms、中位 50 ms、
  最小 3 ms、最大 95 ms（≈20 FPS，抖动大）。

### 上次实验的结局（别再重来）
- 新增过 `frame_ms`（每帧覆写 `APPINFO_nTimer` @0x2b9cc8，来自 appinfo.dat，

### 真正可做、值得做的替代
- **A（推荐，低风险）稳定 tick 抖动**：`TM_Run` 只在 60 Hz 被轮询（16.67 ms
  粒度），60 ms 周期会落在 3~4 个轮询格上 → 这正是 34/50/66 ms 三档抖动的来源。
  把轮询粒度提到 240 Hz（或按 deadline 精确 sleep）可把 ±16 ms 降到 ±2 ms，
  画面仍是 ~17 fps 但不再忽快忽慢，且完全不碰引擎状态、不改游戏速度。
- **B** 接受 30 fps / 1.8x 游戏速度折中（上次 Eden 测过能跑，黑屏未逐一归因）。
- **C** 移植层帧插值：hook 全部 `glDrawArrays` 记录/回放 draw list 做运动补偿，
  工作量极大、风险极高，且输入反馈仍受 17 Hz 逻辑约束。
