## 07:38 实机变卡：是 font.ttf，不是新 NRO

用户同时换了新 NRO 和往卡里放了 `font.ttf`，问哪个导致卡顿。

### 定位
- 日志 `text: loaded font sdmc:/switch/inotia4/font.ttf (50951 glyphs)`。
- `src/text.c` 三条度量函数对**每个字符**调 `FT_Load_Char`，其中两条还带
  `FT_LOAD_RENDER`（真的栅格化位图）：
  - `text_measure_at()` — 宽度（render() 的换行计算里也是逐字符调）
  - `text_ink_height()` — 墨迹上下界
  - `text_ascent_at()` — 基线以上高度
  一屏几十段中文 = 每帧上千次 cmap 查找 + 栅格化；50951 字形的 CJK 字体让每次
  查找更贵 → 换字体后立刻卡。
- 排除项：新 NRO 每帧新增的只有 `lock_points_tick`（3 次 svcQueryMemory）、
  `ui_page_sync`/`touch_state_tick`/`mix_tick`（各一次全局读），合计 <0.1% 帧预算；
  内存也平（246 MB break / 引擎池 3.7 MB 不变）。

### 修法（src/text.c）
- 新增 `glyph_metric(cp, size)` 缓存（1024 槽，开放寻址，key = 码点 + 像素大小），
  一次 `FT_LOAD_RENDER` 同时拿到 advance / bitmap_top / bitmap.rows，三条度量函数
  全部改走缓存。
- 统计行 `text: glyph cache %d hit / %d miss`（每 4096 次访问一行）。

### 实测（Eden，build 07:38:11）
```
text: glyph cache 4073 hit / 22 miss
text: glyph cache 8169 hit / 22 miss
```
命中率 99.7% —— 原来这 8191 次全是 FreeType 调用（约一半带栅格化）。

### 部署
NRO `f831adcebc4378eaaab199501a6048ef`，8.89 MB；build / dist / Eden sdmc 一致。
字体**不需要删**，留着即可，显示正常。

## 20:45 定点：倒数第 2 袋 / 精力加号点不动 = 快捷槽「直连分发」抢走点击

用户上一版（把 12 个快捷槽 rect 挪到 -3000）反馈「没正常」，要求改成

### 铁证（实机 debug.log 19:41）
```
hit: ---- press at (1016,450) root 0x967f9ca68 ----
hit: d1 id 271 rect 973,145 57x396        ← 背包竖列
hit: d2 id 276 rect 973,422 57x57         ← 倒数第 2 袋，手指正落在这里
ui: quick slot 0 code 0017 at (1016,450) -> rc 1   ← 被 HUD 快捷槽抢走
```
`nx_ControlObject_EventProc` 的「快捷槽直连分发」按**固定 `quick_pos[]` 矩形**
（945,395 80x80 等）把 press 直接 `safe_colevent()` 给 HUD 快捷槽并返回 1，

这条路径根本不读控件矩形，`quick_park_all()` 因此每帧与 layout 打架（日志里
`-3000 -> 945,395` 反复出现）。

### 改动（src/main.c，按用户要求改「控件响应逻辑」）
- 删掉 `quick_park_all()` 和 `quick_layout_frame()` 里的 `g_page_owns_touch` 分支，
  快捷槽布局恢复常态。
- `ui_page_live()`：每帧从**活动树**读是否有 1137x640 全屏层，替代 30 帧才刷一次
  且会来回抖的 `g_ui_page_open`；`ui_page_sync()` 用它，`nx_TouchHandle_Event`
  入口再刷一次。`g_page_owns_touch` 现在稳定。
- `nx_ControlObject_EventProc` 前置统一规则（所有指针事件，不只是 ControlButton）：
  - `ctrl_hidden_container(obj)` 命中 → 丢弃（隐藏页控件，泛化原 phantom-button 逻辑）；
  - **`ui_modal_blocks(obj)` → 丢弃**，规则见下；
  - **页面打开时整段禁用快捷槽直连分发**（这是本次真正的修复）。
- `ui_modal_blocks()`：页面打开时，丢弃
  ① HUD 快捷槽（`ctrl_skill_proc`）；② 隐藏容器里的控件；
  ③ 挂在 root 下但**不是全屏页层**的分支（地图/HUD，即「地图 vs 设置」）；
  ④ 六个 80x80 快捷槽组成的弹窗层中，**非最顶层**或标题已不再绘制的那些

## 22:08-22:25 「没有变化」→ 找到真因；随后修掉「开始游戏点不进去」回归

### 真因（务必记住）
**背包/装备/说明页的控件树不在 `ctrl_live_root()` 里。** 引擎给
`nx_TouchHandle_Event` 的 `root` 才是页面自己的 InputLayer root：
```
ui: TouchHandle_Event root 0x210b073878 (live 0x210af6c7d4, 3 children)
```
`ctrl_live_root()` = `probe_ptr(input_engine_virtbase()+0x2b4140)` 是野外 HUD /
标题树。上一版 `ui_page_live()` 只扫它 → 恒 0 → `g_page_owns_touch` 恒 0 →
整套 modal 规则 + 「页面内禁用快捷槽直连分发」**一次都没启用**，
日志 `page owns the touch area` / `off-page control` 全为 0 次，
`ui: quick slot 0 ... rc 1` 照旧抢走 (999,448)。这就是「没有变化」。

### 修复（src/main.c）
- 新增 `root_is_page_tree(root)`：递归 2 层找 `w>=1000 && h>=400` 的层
  （覆盖 1137x640 与 1137x431；`ui_page_is_layer()` 的 h>=500 认不出 1137x431），
  带 4 槽 root+frame 缓存。判定用**本次事件实际分发的 root**。
- `ui_page_sync(void *event_root)`：事件 root 是页面树则缓存到 `g_page_root`，
  明确不是页面树则清空；`hud_tick()` 两处传 NULL 读缓存（pad veto 抢在触摸前）；
  `nx_TouchHandle_Event` 开头与 `have_root:` 之后各调一次，后者用最终 root。
- `colevent` 里 `page_dispatch = (colevent_depth==1 && root_is_page_tree(obj))`：
  页面树内**禁用 HUD 快捷槽直连分发**（核心修复，不依赖帧级标志），
  并打日志 `ui: page root %p owns dispatch ... HUD pre-dispatch disabled`。
- `ui_modal_blocks()` **收窄为只屏蔽 HUD 快捷槽控件 + 隐藏容器**。

### 回归与教训（重要）
第一版收窄前，`ui_modal_blocks()` 会屏蔽 0x0 布局分支；因为
`nx_ControlObject_EventProc` 是 override，父分支返回 0 就**整棵子树不再遍历**，
标题页 6 个 0x0 分支被挡 → `开始游戏` id 10 收不到事件 →
`TouchHandle_Event ... -> 0`，用户反馈「现在开始游戏都点不进去了」。
**教训：在 EventProc override 里屏蔽「分支/容器」= 屏蔽整棵子树，只能按控件
proc 精确屏蔽叶子，绝不能按矩形猜分支。**
