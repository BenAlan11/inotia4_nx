## 快捷键登录到已有图标位置 → 弹窗重复 push → 崩溃

### 现象
用户实机（build 2026-11-19 22:23:50，即 `9da1ef00`）复现：想将另一个技能图标登录到已有图标的快捷键位置时，画面变回原布局后崩溃（此前 crash report 崩在 `CHAR_UpdateAttrFromBuff+0x5c` 的 `ldrh [x24]` 野指针）。用户拖来 `Downloads/debug.log`。

### 根因（日志铁证）
```
4847  desc row 243 rect 830,495 125x55 code 0017 -> 1   ← 点说明页"登录快捷键"
4852  UI_SetPopupProcessInfo(1,9)                        ← 弹出快捷键设置页
4860  nav: page up kind 1 id 150 (6 controls)            ← 弹窗显示
4974  desc row 243 rect 830,495 125x55 code 0017 at (909,514) -> 1  ← 弹窗内点槽(909,514)，被说明页按钮抢走
4985  UI_SetPopupProcessInfo(1,9)                        ← 又 push 一个弹窗（重复）
```
说明页按钮 `id 243` 矩形 `830,495 125x55`（x[830,955] y[495,550]）与弹窗槽位 slot1 `865,475 80x80`（x[865,945] y[475,555]）**重叠**，点击 `(909,514)` 同时命中两者。`desc_row_dispatch()` 不看弹窗状态就抢先派发 → 每点一槽就重复 `(1,9)` push → 弹窗层层堆积 → 状态损坏崩溃。
日志当时 `ui: quick slot` 0 次、`plate: '请选择要设置的快捷键。'` 正常，说明 park 与快捷槽抢事件已不是问题。

### 修复（src/main.c `desc_row_dispatch()`，紧接 dp 校验之后）
```c
if (g_shortcut_popup_frame && g_frame_no - g_shortcut_popup_frame <= 4)
  return 0;
```
弹窗标题"请选择要设置的快捷键。"由 `plate_probe()` 每帧重绘时打时间戳到 `g_shortcut_popup_frame`（[main.c:9724]），新鲜即证明弹窗仍在屏上 → 让点击落到弹窗自己的 6 个槽控件，而不是底层说明页按钮。容差 4 帧以容忍绘制/触摸时序差。

### 问题① R 在快捷登录弹窗失效（已修）
根因：弹窗被 `nav_scan()` 报告为 `NAV_PAGE_SETTINGS` + **0 tabs** + 6 slot。`nav_update()` 的 L/R 只在 `nav_ntabs > 0` 时切 tab；`input_update()` 的 R 又被 `!input_nav_active()` 挡住（弹窗导航激活）→ R 两头都不处理。但 R 的本意是翻快捷槽页（`quick_swap_fire()` 注释写明 field + assign page 都用它，对应屏上 1059,313 翻页按钮）。
修复：在 `src/input.c nav_update()` 的 L/R 切 tab 段之后新增分支——
```c
if (settings && nav_ntabs == 0 && nav_nitems == 6 && !nav_tab_pending &&
    (pressed & HidNpadButton_R)) {
  debugPrintf("nav: R flips shortcut page in assign popup\n");
  quick_swap_fire(); nav_dirty = 1; return;
}
```
`nav_tab_pending` 确保真 tab 重建期不误入。

### 问题② 佣兵页格子点不动（已修，21:57 版）
用户补的日志（build 21:37:06）有铁证：满 6 佣兵时，第二排第 1 格 `id170` 的相对宽度 `+0x28` = `0x5a3767710`（242 亿，正常应 `0x7f`=127）。obj dump：
```
坏 id170: obj ...: aa 2000000003 30 0 7b 5a3767710 72 1cf00000001   ← +0x28=坏宽度
正常 id167: obj ...: a7 2000000003 30 0 0 7f 72 1cf00000001
```
`0x5a3767710` 精确 = `nx_desc_text_scroll` 地址（日志 `desc: draw callback installed (0x5a3767710)`，**4913 行安装 → 4966 行格子宽度就坏**）。Eden 空格不坏、实机满 6 佣兵才坏。
**根因**：`desc_scroll_tick()`（每帧调）无条件写 `*(void**)(sd+0xa0)=nx_desc_text_scroll`，其中 `sd=ctrl_get_data(*(vb+0x2b5a30))`。说明页关闭后 `0x2b5a30` 全局不清零，场景重建后残留指针解析到回收堆；佣兵页里 `sd+0xa0` 正好落在 `id170` 的 `+0x28`（宽度），把函数地址写成了宽度 → 命中区从 x=158 覆盖到屏幕外 → 点第二/三排任何位置都命中 `id170` 跳第二排第 1 格。用户"选中第一排第 1 个再点右侧技能目录后全好"= 真说明页被重建，全局指向正确对象，引擎重排版覆盖了坏宽度。
**修复**（`src/main.c desc_scroll_tick`）：回调安装加 `desc_page_frame && g_frame_no-desc_page_frame<=3` 门槛，只在说明页确实在屏时才写 `sd+0xa0`。`UIDesc_DrawTextScroll` 已由 GOT override 全局接管，写 `data+0xa0` 本就多余，加门槛不漏首次绘制（override 先设 `desc_page_frame`，下一帧 tick 才安装）。
**部署**：NRO `2c9ef5c3e16d13b16706f97d6edec8e1`（build 21:57:57），build/dist/Eden 三处一致。基线 1875 文件、manifest `af9ae47f…`、`config.ini` `b3076640…`、18 存档 `2d5072df…` 全部未动。
