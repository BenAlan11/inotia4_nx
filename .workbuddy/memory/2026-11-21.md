### 新根因：R 只换了数据数组，没改引擎的写索引
日志（build 21:57:57）证据：`nav: R flips shortcut page` → `quick: R swapped right-hand 4 slots`，点击命中槽位正常，但登录写回原页。

反汇编 `UIShortcutMenu_Shortcut_EventProc`（0x161178）：
```
0x1611a8 ldr x8,[x8,#0x9e8]   ← *(vb+0x29e9e8) 得到页指针
0x1611ac ldr x8,[x8]          ← 页值
0x1611b4 madd x19, x8, x9(=6), x0   ← 写槽索引 = page*6 + slot
```
真正的翻页按钮 `UIShortcutMenu_ButtonScrollExe`（0x161368，48 字节）只做一件事：
`page = (page+1)%2`，其中页变量是 `**(vb+0x29e9e8)`（两层指针）。

之前的 `quick_swap_fire()` 只交换 shortcut **数据数组**（slot 0..3 ↔ 6..9），适用于野外 HUD；但在 assign 弹窗里登录写哪格由页索引决定，数据数组交换不影响它 → 视觉翻到第 2 页，登录仍落 page0。

**修复**：
- 新增 `shortcut_assign_flip_page()`（main.c，定义在 `quick_swap_fire` 旁）：读 `**(vb+0x29e9e8)` 页值，写回 `(page+1)&1`（等价 ButtonScrollExe 对 0/1 的行为），带 `probe_mem_ok` 校验和 `quick: assign page %lu -> %lu` 日志。
- `input.h` 加声明；`input.c nav_update()` 的 assign 弹窗 R 分支（settings && 0 tabs && 6 items）改调 `shortcut_assign_flip_page()`，不再调 `quick_swap_fire()`。
- 野外 HUD 的 R（`input_update()` 2120 行）仍调 `quick_swap_fire()`，不变。
