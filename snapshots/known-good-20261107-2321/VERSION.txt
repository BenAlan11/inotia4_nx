CHANGES SINCE 20261106-1945
  All of 2026-11-07. See .workbuddy/memory/2026-11-07.md for the full log.

  1. In-game HUD -> pad. main.c walks the engine's own control tree
     (root 0x2b4140) every 30 frames and hands input.c the live rects and
     objects of ids 1 / 3 / 20 / 21 (+ / - / attack disc / direction pad).
     input.c drives them with TouchHandle_SetSelectedControl /
     SetReleaseEvent -- no virtual finger, so the stick keeps its hold while
     A is pressed. The stick re-asserts its direction every 6 frames.

  2. A / B are routed by layer (ab_layer in input.c):
       AB_POPUP  UIPopupMsg box      -> ButtonOKExe / ButtonCancelExe
       AB_SCENE  UI page on top     -> B taps the page's real x / skip button
       AB_MAP    play HUD           -> A attacks, B stops walking
       AB_MENU   title / save page  -> B taps x, A keeps the old key path
     B's corner button is found in the live control tree, not by measuring
     screenshots: a square in the top-left (x) or a wide bar in the
     top-right (skip, id 381). Both use the engine's public touch queue.

  3. The direction wheel is NOT DRAWN, at the source. UIPlayPorting_Draw's
     virtual-key loop (0x15bf98..0x15c410) is the only code that paints the
     pad, the attack disc, the pressed highlight and the gold rune glow.
     nx_grpx_draw_part() drops those five GRPX_DrawPart calls when the caller
     is inside that range (cfg.no_pad_art). The loop's other logic still runs.

  4. hud_blit_hidden() -- the old "drop any blit inside the pad rectangle"
     filter -- is retired to a no-op. It was a crude screen-region mask that
     deleted inventory icons, map art and page decorations. The GL-level
     hide_pad_zone interception is also off (it stalled the frame loop).
     RULE: to hide UI, find its draw call site and suppress it there. Never
     filter by screen rectangle.

  5. GRPX_DrawPartFlip is an EIGHT-argument function. Its 8th arg (w7)
     selects the X/Y mirror signs. The old seven-argument wrapper left x7
     holding garbage, which made the stat arrows point the wrong way and
     drifted them off their rows. The wrapper now forwards it verbatim.

  6. Misc: pad_probe / flip_arg / tap_buttons / no_pad_art / hud_page_filter
     config switches (one-key rollback for each experiment); tools/win_front.py
     to bring the Eden window forward; start-eden.cmd launcher; the equipment
     page's "Lv. 4 <class>" line is forced to 0xC6B992FF and draw_y -= 5.

THINGS THAT BROKE AND MUST NOT BE REPEATED
  * Calling POPUPSTATE_Event() / the scene key handler directly from our code
    terminated the process with SIGSEGV when B was pressed on a page.
  * Reading UIPopupMsg's OK control (0x2b8d98) after a box closed -- that
    global is NOT cleared -- and passing it to ControlObject_GetAbsoluteRect
    hung the frame loop (0 FPS, "nan ms", watchdog "no frame for 75 s").
  * Returning early from nx_glDrawArrays to hide a quad skipped the function's
    glColor4f / glVertexPointer restore path and froze the renderer.
  * Taking 6 MB PPM screenshots while the stick was held made walking stutter
    (glReadPixels on the software rasteriser).
  * Any filter keyed on "which screen rectangle does this quad land in" eats
    unrelated UI. Suppress the draw call, not the area.

FOOTGUN -- KEEP THE CONFIG
  * cfg.hide_pad_zone still COMPILES to 1 (the default was never flipped).
    A config.ini that lacks the key -- or a run started with no config.ini --
    turns the GL interception ON, and the game will stall after a few frames
    ("0 FPS / nan ms", watchdog "no frame for 75 s"). Always ship a
    config.ini that says hide_pad_zone = 0. config.prod.ini in the repo root
    and dist/switch/inotia4/config.ini both do.
  * pad_probe must stay 0: any value >= 2 drops pad-zone quads, and 3 wrote
    6 MB PPMs while the stick was held (that is what made walking stutter).

KNOWN GAPS
  * A does not confirm UI_PopupProcess boxes (e.g. the "路障" event message).
    Those are not UIPopupMsg. Do not use UIPopupMsg globals to reach them;
    find the confirm button in the live control tree instead.
  * skip was added from the control tree (id 381) but not yet confirmed in
    a real cutscene.
  * The gold rune wheel / touch feedback should now be gone at the source;
    re-check while walking before calling it finished.
