CHANGES SINCE 20261108-1350
  One feature: gamepad keys now fire the six quick slots. See
  .workbuddy/memory/2026-11-08.md "手柄快捷键映射" for the full log.

  1. Mappings (Xbox labels; Eden maps Xbox A -> NS B and Xbox B -> NS A, so
     the NS bit order is X, Y, B, A). Only active while hud_mode &&
     cfg.quick_layout.
       d-pad LEFT  -> lower-left slot 4 (20,530)
       d-pad RIGHT -> lower-left slot 5 (120,530)
       RT (NS ZR) + X -> right cross up    slot 0 (945,395)
       RT (NS ZR) + Y -> right cross left  slot 1 (865,475)
       RT (NS ZR) + A -> right cross right slot 2 (1025,475)
       RT (NS ZR) + B -> right cross down  slot 3 (945,555)
     RT = Xbox right trigger (NS ZR, axis 5 in qt-config.ini). R = Xbox RB
     (NS R) is still the page-swap key; the two are different buttons.

  2. input_update() edge-triggers press/release for all six keys and calls
     quick_slot_fire(slot, press) in main.c. That uses the cached HUD control
     object quick_objs[slot] and the button centre from quick_pos, then
     input_fire_control() (a wrapper over hud_event_at) presses the control
     object directly via SetSelectedControl / SetReleaseEvent -- the SAME path
     as the stick, the attack disc and the A button. No touch injection, so
     the HUD touch block and the control-tree dispatch order cannot eat it.
     The assign-page group quick_objs[6..11] is deliberately NOT used here.

  3. Keys are bound to SCREEN POSITIONS / control objects, not to shortcut
     data. R's four-slot data swap therefore leaves every key on the same
     button ("切换后同样位置"). No draw code was touched in this round; the
     page-swap icon stays hidden from the 13:50 build.

  4. ZR is no longer an alias of the A button (it used to be
     `down & (A|ZR)`), otherwise holding RT would also attack. While RT is
     held, A/B neither attack nor stop walking, and want_down excludes ZR so
     a menu does not get a stray injected touch.

THINGS THAT BROKE AND MUST NOT BE REPEATED
  * Calling the engine's per-scene key handler from port code -- directly,
    through the 0x29eb90 slot, or after PT_LOAD|PF_X validation -- stalls the
    frame loop (0 FPS / nan ms, debug.log stops with no watchdog line).
    menu_key_press() was DELETED. Do not reintroduce a guarded version.
  * POPUPSTATE_Exist() returns 0 on the character page. Any "is this a popup
    page" test based on it misclassifies that page as AB_MENU.
  * Assuming UIPopupMsg is the only message box. The "路障" box is a
    different class; popup_press()/UIPopupMsg_ButtonOKExe never fires for it.
    (This is the open defect at freeze time.)
  * Reading UIPopupMsg's OK control (0x2b8d98) after the box closed: that
    global is stale and ControlObject_GetAbsoluteRect on it hangs the loop.
  * Matching the shortcut-assign page's slots by control id. Their ids change
    between sessions (334..339 vs 231..236). Match the event proc instead.
  * Assuming a one-shot rect write sticks on that page: it resets rects every
    frame, so quick_layout_frame() re-applies every frame with probe_mem_ok.
  * Incremental builds after changing config.h. Use `python build.py --clean`.
  * so_try_find_addr_rx() returns uintptr_t; assigning it to void* without a
    cast is a hard clang error (-Wint-conversion).
  * Parking the d-pad / action-disc control rects off-screen to "stop them
    answering touches". The user explicitly rejected this: the rule already
    exists in hud_touch_blocked(), and input.c drives those objects directly.
    Only the six quick-slot rects are exempt from the block.
  * Filtering quads by screen rectangle to hide UI. Suppress the draw call
    site (as no_pad_art does), never mask an area.
  * Ordering the four face keys by NS button name: Eden swaps Xbox A/B, so
    {X,Y,A,B} reverses the physical A/B. Use {X,Y,B,A}.

FOOTGUN -- KEEP THE CONFIG
  * cfg.hide_pad_zone still COMPILES to 1. A config.ini without the key turns
    the GL interception on and stalls the game ("0 FPS / nan ms"). Always
    ship hide_pad_zone = 0.
  * quick_layout / quick_pos must be present and identical in all three:
    config.prod.ini, dist/switch/inotia4/config.ini, Eden sdmc config.ini.
    A missing/partial quick_pos leaves the ORIGINAL arc while the touch
    exemption is still enabled -- taps would be let through in wrong places.
  * The Eden sdmc config.ini also carries the user's log_level = 3 and
    tap_script = "960,919@600". Do not overwrite it with the production file
    when deploying; only sync the keys the code reads.
  * pad_probe must stay 0.
  * Do not edit %APPDATA%\eden\config\qt-config.ini: Eden already maps the
    Xbox pad to NS buttons. The pad key mapping lives in input.c only.

KNOWN GAPS
  * "路障" and other UI_PopupProcess-style message boxes do not answer A on
    their 确认 button. To fix, find that box's own OK control in the live
    control tree and press it (or call its own event proc); do NOT call the
    scene key handler or poke the stale UIPopupMsg OK global.
  * A on a UI page is ignored: it does NOT add stat points or confirm there.
  * The R swap assumes the HUD reads shortcut slots as array[page+i] with
    i=0..5. If the right-hand four do not change (or the lower-left two do),
    locate the slot index in each control's data instead.
  * Hiding the field HUD's swap icon uses the draw call's anchor near
    1059,313. A future layout change could move that anchor.
  * The pad mappings, the R swap and the touch exemption all still need one
    full play-test.
