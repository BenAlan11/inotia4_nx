CHANGES SINCE 20261108-1800
  See .workbuddy/memory/2026-11-08.md for the full log.

  1. A on a UI_PopupProcess info box ("路障", NPC dialogue) now taps its real
     确认 button. Those boxes are not UIPopupMsg (no 0x2b8d78 base control), so
     popup_on() was false and ab_press() dropped A. ui_confirm_button() finds
     the dialog body by control TYPE + tree shape (a ControlScroll text child
     plus a ControlButton child under a full-screen parent, button below the
     text and wider than tall), then confirm_tap() taps its centre through the
     engine's public touch path, exactly like B on the x button. A is only
     routed there on AB_SCENE. No engine internal / scene key handler is called.

  2. The NPC dialogue option list is UIChoice. UIChoice_CreateControl
     (0x145384) keeps its controls in globals: +0x2b49e0 is a heap block of
     one 0x7f8-byte record per option, freed and NULLed by UIChoice_Exit (that
     non-NULL value is the engine's own "page is open" flag -- the control
     pointers themselves are NOT cleared and go stale); +0x2b49e8 frame,
     +0x2b49f0 scroll, +0x2b4a00 content, +0x2b4a08[] one ControlButton per
     row. ui_choice_button() checks the open flag and the frame's own rect,
     then hands 0x17/0x18/0x19 straight to the row control (falling back to
     the content control when row rects carry a parent-local origin). Same
     direct dispatch as the six quick slots.

  3. RT+X/Y/A/B order corrected. face[4] is now {X, Y, A, B}; the 14:23 build
     tried to compensate for Eden's qt-config.ini (Xbox A -> NS B, Xbox B ->
     NS A) with {X, Y, B, A} and play testing showed the physical A/B reversed.
     Never infer the order from the config again -- the user's test wins.

  4. The two pad-bound left-column buttons (control ids 1 and 3) no longer
     draw. They were already bound to pad keys and already blocked from real
     screen touches (HUD_BTN_PLUS / HUD_BTN_MINUS in hud_r[]), so ONLY the
     icon needed removing. UIPlayPorting_Draw SHARES its GRPX_DrawPart call
     sites with every other HUD button, so a pure ra range would also hide the
     basket button. hud_scan_node() publishes id 1/3's own absolute rects from
     the engine's control tree; nx_grpx_draw_part() cuts exactly those two
     calls, confined to HUD_DRAW_LO..HI. Call-site cut, not a rectangle mask --
     hud_blit_hidden() is still a no-op. Switch: cfg.no_pad_art.

  5. Emphasis colour now comes from the ENGINE's own table.
     X_TEXTCTRL_GetColorFromCode (0x144f3c) reads 25 entries at module+0xbb9c8,
     indexed by (code - 'A'), each 0xAABBGGRR. The port used a hand-written
     10-letter subset (values guessed: $G was green where the engine says
     grey), so codes the game actually uses but that list omitted -- $T, $Q,
     $L, $O, $P, $V -- fell through to the base pen and read as white. That is
     the "emphasis colour disappeared" symptom; src/text.c itself had NOT
     regressed (byte-identical to the 11-04 18:46 build the user confirmed).
     text_set_engine_base() runs after so_finalize(); colour_for_code() now
     converts the engine entry to 0xRRGGBBAA. $B stays the closing code that
     returns to the caller's pen and is the ONLY code that does ($W is now
     genuinely white). The legacy subset is kept as a pre-map fallback.
     Diagnostics: `subraw:` (independent of dlg_probe's 16-row table, which
     the character page fills first) prints the story body's raw string and
     whether it still has $ codes; `rich: colour run col %08x` prints each
     non-base run.

THINGS THAT BROKE AND MUST NOT BE REPEATED
  * Calling the engine's per-scene key handler from port code -- directly,
    through the 0x29eb90 slot, or after PT_LOAD|PF_X validation -- stalls the
    frame loop (0 FPS / nan ms, debug.log stops with no watchdog line).
    menu_key_press() was DELETED. Do not reintroduce a guarded version.
  * POPUPSTATE_Exist() returns 0 on the character page. Any "is this a popup
    page" test based on it misclassifies that page as AB_MENU.
  * Assuming UIPopupMsg is the only message box, or matching the
    shortcut-assign page's slots / UIChoice's rows by control id. Their ids
    change between sessions. Match the event proc or the tree shape instead.
  * Reading UIPopupMsg's OK control (0x2b8d98) after the box closed: that
    global is stale and ControlObject_GetAbsoluteRect on it hangs the loop.
  * Assuming a one-shot rect write sticks on the shortcut-assign page: it
    resets its rects every frame, so quick_layout_frame() re-applies every
    frame with probe_mem_ok.
  * Incremental builds after changing config.h OR text.h. Use --clean.
  * so_try_find_addr_rx() returns uintptr_t; assigning it to void* without a
    cast is a hard clang error (-Wint-conversion).
  * Parking the d-pad / action-disc control rects off-screen to "stop them
    answering touches". The user explicitly rejected this: the rule already
    exists in hud_touch_blocked(), and input.c drives those objects directly.
    Only the six quick-slot rects are exempt from the block.
  * Filtering quads by screen rectangle to hide UI. Suppress the draw call
    site (as no_pad_art does), never mask an area. A pure ra range is fine for
    the wheel, but NOT for HUD buttons that share a call site -- there, use
    the control's own rect inside that ra range.
  * Maintaining a hand-written $X colour-code table. The engine's table at
    +0xbb9c8 is the only source of truth; missing entries silently turn
    emphasis white.
  * Ordering the four face keys by NS button name from qt-config.ini: the
    14:23 attempt reversed the physical A/B. Use the user's tested order.

FOOTGUN -- KEEP THE CONFIG
  * cfg.hide_pad_zone still COMPILES to 1. A config.ini without the key turns
    the GL interception on and stalls the game ("0 FPS / nan ms"). Always
    ship hide_pad_zone = 0.
  * quick_layout / quick_pos must be present and identical in all three:
    config.prod.ini, dist/switch/inotia4/config.ini, Eden sdmc config.ini.
    A missing/partial quick_pos leaves the ORIGINAL arc while the touch
    exemption is still enabled -- taps would be let through in wrong places.
  * The Eden sdmc config.ini also carries the user's log_level = 3 and
    tap_script = "960,919@600". Do not overwrite it with the production file
    when deploying; only sync the keys the code reads.
  * pad_probe must stay 0. string_draw must stay 1 (2 disables our text).
  * Do not edit %APPDATA%\eden\config\qt-config.ini: Eden already maps the
    Xbox pad to NS buttons. The pad key mapping lives in input.c only.

KNOWN GAPS
  * This build's two new changes (hidden menu-button icons, engine $X colour
    table) and the RT A/B order correction have NOT been play-tested.
  * If `subraw: ... codes 0` on a story line that should be coloured, the
    engine stripped its $ codes upstream; that is a different layer and needs
    its own investigation (do not hard-code colours).
  * A on a UI page other than a UIPopupMsg / UI_PopupProcess box is still
    ignored: it does NOT add stat points or confirm there.
  * The R swap assumes the HUD reads shortcut slots as array[page+i] with
    i=0..5. If the right-hand four do not change (or the lower-left two do),
    locate the slot index in each control's data instead.
  * Hiding the field HUD's swap icon uses the draw call's anchor near
    1059,313. A future layout change could move that anchor.
  * dlg_probe still has a 16-row table; only subraw/rich logs are reliable for
    story dialogue.
