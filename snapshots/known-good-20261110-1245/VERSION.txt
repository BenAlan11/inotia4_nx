CHANGES SINCE 20261108-2146 (full logs in .workbuddy/memory/)
  1. Save slots reading ERROR(00) -- ROOT CAUSE FIXED. libgame.so is an
     Android bionic binary: its open(..., 0x241) means O_WRONLY|O_CREAT|
     O_TRUNC with bionic's O_TRUNC = 0x200. The port passed flags straight to
     newlib, where 0x200 is O_CREAT and O_TRUNC is 0x400, so save files were
     never truncated. A shorter save left a stale tail; the engine decrypts
     with len = filesize-3 and the checksums no longer line up. Three layers:
       * libc_shim.c translates bionic -> newlib flag bits for every engine
         open() (shim_open is only on the engine import table).
       * nx_save_nk() rewrites exactly len+3 bytes with "wb" when the file
         is still too long (ftruncate is unreliable on Switch devoptab).
       * nx_load_nk() / boot check scan for the longest valid encrypted
         block with the ENGINE'S OWN decryptor and trim the stale tail.
     The key inotia4-switch-save-v1 was never wrong: thpcheckslot1.dat
     decrypts to "2|011110|99|99|99|99|99|END|".
  2. Attack key A -> Y in hud_update(); A stays the menu/confirm key.
     RT (NS ZR) is a modifier for X/Y/A/B on the right-hand quick slots and
     d-pad left/right on the lower-left pair; R (Xbox RB) swaps the right 4.
     Face-key order is the user's TESTED order X, Y, A, B -- do not derive it
     from qt-config.ini.
  3. Settings-page pad navigation: L/R switch the six tabs, A enters the
     content, d-pad moves the cursor, B backs out, STAT mode adds/subtracts
     character points. The navigator MUST run outside the `!hud_mode` branch:
     opening a settings page leaves the HUD controls in the tree, so
     hud_active stays 1 and that branch never runs.
  4. The same gold shape-following cursor on the title / save / class pages.
     Page detection reads the control TREE, never dynamic ids: every
     1137x640 child of the root is a layer, the LAST recognisable one is on
     top (class screen sits over the save list, which sits over the title).
     The in-field HUD tree has no such layer so the navigator stays off.
     Class page taps step around the stale save rows underneath
     (nav_safe_point scans the badge's own band for a row-free y).
  5. THIS BUILD: the title page's gold cursor was drawn on the padded HIT
     box (369x124 / 300x92) and looked much bigger than the visible flat
     oval. GL quad diagnostics showed the engine draws the buttons at
     exactly those rects, and the atlas
     data/resources/common/game_res/UI_TITLEMAIN_BUT_cn_s_001.png has alpha
     bounds 357x77 / 292x63 / 292x63 -- all 4.63:1. nav_title_art() now
     shrinks the highlight to 92% of the hit width with that measured
     aspect, keeps tx/ty at the original control centre (tap must not move),
     and sets NAV_SHAPE_ELLIPSE. nav_gold_cursor() draws a 220-point ellipse
     with a tighter 2/1/0 px halo, so it reads as a continuous gold line.

THINGS THAT BROKE AND MUST NOT BE REPEATED
  * Calling the engine's per-scene key handler from port code (directly,
    through the 0x29eb90 slot, or after PT_LOAD|PF_X validation) -- stalls
    the frame loop. menu_key_press() was DELETED.
  * POPUPSTATE_Exist() returns 0 on the character page.
  * Matching the shortcut-assign slots / UIChoice rows / front-end pages by
    control id: those ids change every launch. Match the event proc or the
    tree SHAPE instead.
  * Drawing a highlight on the control rect when that rect is a padded HIT
    box. Read the atlas alpha bounds / the real art quad first.
  * Passing bionic flag bits straight to newlib, or assuming a short save
    overwrites a long one without O_TRUNC.
  * Incremental builds after changing config.h / text.h / input.h. --clean.
  * so_try_find_addr_rx() returns uintptr_t; cast before assigning to void*.
  * Parking the d-pad / action-disc rects off-screen, or letting a settings
    page whitelist ALL touches (the HUD veto must stay intact outside the
    navigator's own rects).
  * Filtering quads by screen rectangle to hide UI; cut the draw call site.
  * A hand-written $X colour table (use +0xbb9c8) or GL_CURRENT_COLOR as the
    story body's pen (TEXTCTRL2 uses GRPX_SetFontColor).

FOOTGUN -- KEEP THE CONFIG

    turns on and the game stalls at 0 FPS / nan ms.
  * quick_layout / quick_pos identical in all three ini files.
  * The Eden sdmc config.ini also carries the user's log_level = 3 and
    tap_script. Do not overwrite it with the production file.
  * pad_probe = 0, string_draw = 1, no_pad_art = 1.
  * Do not edit %APPDATA%\eden\config\qt-config.ini.
  * Do not touch the user's save/ directory when deploying. Only replace
    inotia4_nx.nro; verify file count / total bytes / directory md5 before
    and after.
